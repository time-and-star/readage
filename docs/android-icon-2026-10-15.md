# Android 图标延迟出现黑边：2026-10-15 检查记录

用户明确描述：刚安装后为新透明图标，没有修改设置，过一阵自动恢复成此前带黑边的旧图标。背景必须保持透明，不能改用橙底、白底或其他实色底层。这是 N13 的失败场景；安装后第一张透明截图不能代表通过。

## 已确认的事实

- 手机为 vivo V2190A、Android 13，桌面 `com.bbk.launcher2` 版本 `14.0.3.140`。
- 手机实际 APK SHA-256 仍为 `63cd4f1f6d56c3ed4916afce499a584732252b74e17d70a186a9533f584208d9`，与上次交付的新包一致。
- 当前包和上次安装前的备份包，都选择正式 `readge_launcher` / `readge_launcher_round` 各五种密度透明 PNG；16 张品牌 PNG 逐像素对应，未发现活动图标覆盖或另一启动别名。母图没有变化。
- 同一手机的系统“应用信息”页显示新橙色图案，外部没有黑底；桌面截图存在明显黑色外框，用户确认这是旧图标。该差异定位到桌面显示处理，不能仅据截图确定具体后台触发点。
- 采集时系统为浅色模式，`mNightMode=1 (no)`、`mComputedNightMode=false`，有黑边。不能简单归因于当时正在启用深色模式，也不能排除之前的重绘或缓存。
- 本轮没有清除桌面缓存 / 布局、切换全局主题、卸载应用或修改学习数据。曾准备的实色底适配方案已撤回，原 PNG、透明背景与当前安装包保持；未产品构建、同步、打包或重新安装。

证据位于 `output/android-icon-2026-10-15/` 的 `screen.png`、`system-app-info.png`、`installed-hash.txt`、`launcher-settings.json`；包内检查位于 `output/icon-audit-2026-10-15/` 的 `apk-icon-comparison.json` 与 `current-apk-icons-hardened-verification.json`。手机画面仅用于本地诊断，未作为公开发布附件。

## 与旧图标回填吻合的版本缓存机制

本机公开的 vivo 桌面系统包静态检查确认：`IconCache` 的 `z0.c.o/r` 从桌面版本缓存或 `PackageManager.getPackageInfo().versionCode` 获取当前版本；`z0.c.R` 在偏移 `0x00a9` 比较此版本和磁盘图标的 `appversion`。相等时解码旧图标 bytes，并在 `0x00f7` 放回内存图标缓存；不等时到 `0x0113`，通过 `Y(...)` 从系统图标重新生成。该分支没有同时比对 APK 哈希或更新时间。

首次桌面数据收集的后台 `a1.e$a.run()` 从持久化图标读取 bytes 和 appversion，再调用上述分支，日志标识为 `putFirstScreenByteToCache`。因此多个不同更新包持续使用同一个 `versionCode=2`，会让旧图标仍满足这个版本有效条件，与“先出现新图标，过一阵旧图标回来”的时间顺序吻合。尚未读取该应用的私有桌面缓存或捕获这次实际命中的运行日志，故将此作为有静态机制证据的根因线索，不把动态因果判为已经验收。

限定证据：`output/android-icon-2026-10-15/launcher-static/class-6.txt` 第 3836 行附近的版本比较及缓存回填、同文件第 7090 / 7568 行附近版本来源，以及 `dump1.txt` 第 2984 行附近的后台入口、`dump2.txt` 第 2060464 行附近的系统版本读取。

Android 源码版本现由 `2 / 1.0.1` 升到 `3 / 1.0.2`，让上述分支能够拒绝版本 2 的旧图标 bytes。正式透明母图、16 张 PNG、普通和圆形图标路径均保持。新版本未构建、未同步、未生成包或安装，手机仍为版本 2；增版效果待新包实际验证，不能承诺已经删除桌面缓存或保证其他厂商所有重绘路径。

构建前新增版本检查：在生成资源或覆盖旧 APK 前，读取上一包真实版本；仅旁车与旧 APK 哈希匹配时信任旧输入标识。新输入必须严格递增 versionCode，禁止降级；完全相同输入可同版本重建。常规 clean 删除旧 APK 后，可用与交付旁车精确匹配的最终图标验证记录恢复旧身份，不要求保留第二份大 APK。生成资源后、前端编译前会再核对一次输入。当前只读预检已确认旧包为 2、新源码为 3，增版允许，强行沿用 2 会被拒绝，见 `output/icon-audit-2026-10-15/package-version-preflight.json`。

## 透明图标交付校验

构建流程已接入最终 APK 的图标校验，再记录交付。检查真实母图哈希、16 张生成 PNG、应用图标真实指向、五种密度、透明像素、活动覆盖和额外主题 / XML 配置；版本读取当前 Gradle 配置，避免沿用过时版本的验证。当前逐像素验证依赖 Windows 的 System.Drawing，其他主机的 APK 交付会在构建前明确停止，不能跳过校验；当前仓库使用的 Windows 构建流程不受此限制。

15 项图标策略、14 项版本防复用及 26 项平台记录检查合计 55 项通过，应用类型检查通过。版本增到 3 之前，已有版本 2 APK 按其原 `2 / 1.0.1` 身份通过强化后的只读图标校验；版本 3 尚无新包。这些验证只证明旧包仍采用透明原图、源码和交付检查符合新规则，**不证明手机桌面延迟回填旧图标已经修复**。
