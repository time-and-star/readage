# 启动画面整理（2026-10-15）

> 此文保留第一版书页方案的历史源码阶段记录。用户随后明确否决该外观，选择橙色艺术方向，并要求删除左上小图标 / 文字；当前方案与新验证见 [橙色启动页重做](startup-redesign-2026-10-15.md)。本页旧截图和检查不作为当前视觉通过证据。

用户在实际已安装的 Android 1.0.2 中反馈两个启动画面：系统首屏图标过大；随后资源与档案初始化提示以无排版文字出现在左上角，并要求“艺术一点，美观一点”。本轮先完成源码和隔离验证，不运行产品构建、Capacitor 同步、安装包生成或安装。

## 画面与流程

- Android 系统首屏保留正式透明品牌图案，用启动专用 inset 缩小到约 72dp 的画布；原生窗口、状态栏与导航栏采用暖纸色和深色图标。没有修改桌面启动图标、透明 PNG、入口或版本号。最终系统渲染尺寸仍待新包设备验收。
- 共用 HTML 第一帧即显示完整启动画面：暖纸底、细线书页、小型品牌图案、衬线字标和“字里行间，渐入佳境。”。启动 CSS 独立于应用模块，避免等待 JavaScript 时空白或闪出左上角默认大字。
- 共用启动入口依次显示资源检查（Android）、档案读取和页面打开阶段。没有假百分比、强制等待或提前打开应用。8 秒后补充首次 / 更新资源可能较慢的提示；正常完成后立即由应用替换。
- 失败沿用同一画面，停止旋转、显示具体原因和至少 44px 高的重试按钮。重试重新显示启动壳，单次初始化进行中不允许另一轮并发；每次尝试清理慢提示定时器。错误用 `textContent` 显示。
- 窄屏、横屏和安全区保留内容与触控空间；系统减少动态效果时停止旋转。Windows 服务启动前的独立窗口也对应暖纸色和书页线稿，保留原有进度消息接口及严格的本地页面安全策略。

代码为 `index.html`、`src/startup.css`、`src/lib/startupScreen.ts`、`src/main.tsx`、`desktop/splash.html`、`android/app/src/main/res/values/styles.xml`、`android/app/src/main/res/drawable/readge_splash_mark.xml` 与 `capacitor.config.ts`。

没有调整数据库、档案迁移、恢复策略或模型完整性校验。启动仍保持 Android 平台初始化 → SQLite 水合 → 动态加载 App / MemoryProvider 的顺序。约 1.34 GiB 正式运行资源的校验仍会耗时，本轮美化不等同于启动性能改善。

用户功能编号为 N01 / N02 / N10 / N11 / N14，另核对 N13 的正式透明品牌图案未变。共用初始化、原生数据库适配、旧 WebView 兼容、启动模块延迟加载 16 项通过；透明图标策略 15 项、Android CSS 兼容 7 项通过；`npm run lint` 通过。隔离数据库测试首次受沙箱本机连接限制，使用同一临时测试目录规则在沙箱外重跑后通过，没有访问真实学习库。

隔离 Chromium 的共用启动页 8 组 / 150 项检查通过，覆盖 320px / 360px 窄屏、1280px 桌面、横屏、安全区、减少动态效果、8 秒慢提示、两种读取失败、连续重试与完成挂载。独立 Windows 启动 HTML 另有 3 组 / 17 项检查通过，覆盖 540×281 和 540×320 内容区、长进度文案及减少动态效果；保留原样 CSP、无外部资源依赖。所有报告无未捕获浏览器异常。
