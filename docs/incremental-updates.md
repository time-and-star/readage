## 2026-10-27 发布基线覆盖修复

0.1.9公开包与本机分发的重编译包具有不同SHA；首批0.1.10仅覆盖前者，后者会完整下载。本轮已补发重编译包的35.4MB差分，目标完整EXE不变，详见[真实包复现和补发记录](delta-coverage-2026-10-27.md)。

后续发布应按实际分发过的完整包SHA清点基线，包括同一版本号的不同构建；以实际旧安装器缓存和真实目标包验证选择模式、请求下载量及完整还原结果。发布了某一条差分或小夹具通过，不能代替实际用户基线可命中的证据。缓存缺失或未知SHA仍安全回退完整下载，并保留明确原因。补发仅新增不可变差分和描述，不覆盖既有完整包或差分。

## 当前策略：完整安装包差分、后台任务与续传（2026-10-18，源码阶段）

用户在研究各版本用户的更新等待后明确“开始吧”，授权实现完整安装包的差分传输、后台下载、暂停 / 继续和断点续传。目标仍是同一最新版完整 EXE / APK，复用准确旧包的相同字节，在本机还原与官方原件逐字节相同的目标；不删模型、词典或功能，不要求逐版安装。历史网页补丁的启用、目录切换和 revision 通道保持停用。本节覆盖下文2026-10-17的“仅完整下载”限制，保留完整包发布及正常系统安装。

`website/update-protocol.mjs` 的 `installer.deltas` 为可选列表，最多32个精确基线 SHA-256。每项给出原始差分数据和描述文件的大小、摘要；文件名固定为 `完整包文件名.from-基线SHA.delta` 及同名 `.json`，只从固定官网 HTTPS 下载。旧接收器忽略新增字段，继续完整下载。新客户端同时固定版本、Android build 和目标 SHA；展示版本相同但 build 或包内容变化时不复用旧 ready。没有更新器的旧用户仍需一次包含新接收器的完整升级。

Windows 从受控安装器缓存寻找精确基线，兼容历史 `readge-` 基线文件名，正式目标名仍固定为 `ReadAge-`；Android 只读已安装 APK `sourceDir` 及受控完整包缓存。差分数据加描述文件达到完整包90%时改走完整下载；发布工具默认按相同总流量执行80%阈值。无基线、差分不兼容或损坏时回完整下载；临时断网则保留差分断点供继续，不因为网络失败清掉补丁再取整个包。还原全程流式读写，完整目标校验通过后才进入安装前的保存 / 系统确认流程。差分仍需要完整输出空间、本机读写与校验，不能用传输量替代总耗时验收。

下载任务与提示卡片分离，状态和固定目标保存于各端 `installer-updates/`。卡片可收起，保留小进度入口；暂停保留字节，明确取消才清本次任务。服务器返回206时核对范围、总长和剩余大小；返回200则安全从头写入，不能追加拼错；最终仍校验完整摘要。断网有限退避重试，退出 / 进程回收后可继续。已准备的包和“稍后安装”入口不依赖官网在线，不把稍后安装当成永久忽略。安装前仍等待学习记录与SQLite写入，失败不打开系统安装器。

Android 新增独立 `dataSync` 前台Service、低打扰进度通知、暂停 / 继续 / 取消动作和活跃阶段有超时保护的唤醒锁；Activity / WebView 销毁不直接取消下载。系统限制或主动停止后保留任务进度，下次打开可继续；不承诺系统强停后自动复活。Android 12–13与14以上使用同一正式下载能力，通知授权、锁屏、系统回收和系统安装仍需正式APK真机验收。浏览器网页缺少安装本机服务的权限，保留明确人工升级提示；本轮没有把网页本身当成本机更新器。

### 准备发布差分（产品检测通过、已有新包后执行）

`npm run updates:prepare-deltas -- --target <已有目标完整包> --filename <正式ReadAge文件名> --target-map <目标.blockmap> --target-sha <目标SHA> --base <旧完整包> --base-map <旧.blockmap> --base-sha <历史SHA> --output <独立输出目录>`。重复 `--base / --base-map / --base-sha` 可让多个旧包各自直达同一目标；默认 map 为安装包名加 `.blockmap`。APK本地名为 `app-debug.apk` 时，必须用 `--filename ReadAge-版本-android.apk` 指定正式文件名。此工具只读已有原件、逐块比对、生成原始差分及描述，不构建、不改正式 `releases.json`、不上传或安装。

先上传并校验完整包、差分数据和描述文件，再将输出的 `installer.deltas` 合入对应真实版本清单；源包、目标包和签名保持。官网NGINX白名单已在源码增加固定差分路径，并对下载文件关闭gzip以保持摘要 / 长度 / Range对应相同字节，正式配置与文件尚未部署。发布后的固定文件名内容不可覆盖；保留完整包及仍在使用的历史基线窗口，新版本发布不替换正在下载任务的目标。最多32个发布基线以外的用户仍可完整升级。具体U26–U37及本轮源码 / 测试 / 界面结果见 `docs/user-feature-acceptance.md`、`docs/platform-parity.md`。

## 用户流程

“我的学习 → 设置与工具 → 检查更新”沿用现有入口。兼容的新版显示“下载小更新”，只下载变化的网页文件；未变化的文件由已安装版本或上一个小更新复用，不重新传输模型、词典、文章、附件和学习档案。下载时显示文件进度和已下载字节，可以取消；取消、断网、哈希错误及签名错误均保留当前运行版本。

全部文件准备好后显示“重启更新 / 稍后重启”。准备好的小更新独立保存，退出后可从手动检查入口继续使用。点重启时先等待本机学习记录全部保存；保存失败不切换。浏览器 / Windows 重新加载本机页面，Android 切换 Capacitor 本机文件目录，URL origin、SQLite 与学习档案位置保持。新界面挂载后确认启动成功；120 秒内未确认则回退，下次启动发现未确认的版本也会回退。坏版本的 revision 不重复应用，应发布更高 revision 的修复版。

这里的“重启”是重载阅读界面，不重启系统，也不在阅读途中自动安装。

用户后续要求常规应用更新不跳浏览器：Windows / Android 在应用内下载完整安装包，显示字节进度、支持取消、重开保留已下载包，安装前再次校验摘要。Windows 主进程只接受本窗口受控 IPC，请求只能提供版本，不能指定网址、文件路径或执行命令；保存学习记录、停止自有服务后打开正式 NSIS。Android 原生从固定官方 HTTPS 下载到私有缓存，再核对包名、版本、SHA-256 与当前 APK 签名，通过 FileProvider 交给系统安装器；首次系统“允许安装应用”及安装确认由用户操作，不静默安装。系统要求参考 [Android PackageManager](https://developer.android.google.cn/reference/android/content/pm/PackageManager) 和 [安全文件共享](https://developer.android.com/training/secure-file-sharing/setup-sharing)。本地浏览器缺少本机服务安装权限时直接提示升级服务，不默认跳外站。

“设置与工具”的“关于我们”位于“检查更新”和“词典设置”之间；这是用户明确要求的官网入口，点击打开 https://readage.xyz，与应用内更新分开。

## 三端边界

| 范围 | 本地浏览器 | Windows | Android |
| --- | --- | --- | --- |
| 界面、前端业务、图片、字体及其他允许的网页静态资源 | Node 接收、按文件更新；仅生产服务开启 | 同 Node 接收，Electron 原窗口重新加载 | 原生 Java 验签、下载，Capacitor 加载私有目录 |
| 外壳 / Node 服务 / Java / C++ / 插件 / 依赖及内置词典或模型变化 | 更新本机服务与对应资源 | 安装兼容的新版 | 安装兼容的新 APK |
| 原有模型、词典、学习数据 | 小更新不写入 | 小更新不写入 | 小更新不写入 |

本轮**没有实现模型或内置词典的独立差分下载，也没有实现 APK / EXE 二进制差分安装**。此类更新会改变外壳兼容指纹，继续走完整安装版，不会尝试靠小包省略功能。小更新限制为已经存在的原生 / 服务能力支持的网页修改，不能将“所有更新均无需安装包”标为完成。首次安装仍需完整离线资源，当前发布方式不改为首次联网下载模型。

## 发布操作（用户检测通过后执行）

1. 用对应产品构建命令产生已经记录、与当前源码一致的 `dist/` 或 `dist-android/`。构建脚本生成 `readage-shell.json`，包含目标、外壳指纹和可信公钥。Android 仍先构建再 Capacitor 同步。本轮已执行，并保留各端构建 / 包旁车。
2. 分端生成发布文件，例如 `npm run updates:prepare -- --platform android --revision 1 --version 1.0.6`；另两端用 `web` / `windows`。revision 在每个平台持续递增，不能用版本字符串替代。命令只读取已有构建，不构建、不同步、不安装、不改线上清单；不匹配当前源码或目标的构建会被拒绝。
3. 输出位于 `website/.data/patches/`：`manifests/{platform}.json` 为 RSA-SHA256 签名信封；`files/{sha256}` 为按内容寻址的静态文件。将这一目录部署到官网所用 `READAGE_WEBSITE_DATA_DIR/patches/`，并保持旧文件可下载，以免发布期间旧清单的客户端中断。私钥不能部署进公开文件目录。
4. 审核命令输出后，把输出的 `bundle` 中 `revision / runtime / version / bytes` 写进 `website/releases.json` 的对应端。`manifest` 是说明用路径，不需要写进 bundle。原外壳 `version / build` 保持真实可下载安装版本；小更新版本用 `bundle.version`。原生升级则先发布真实新版安装包并更新外壳版本，不能只发布不兼容的小包。
5. 官网分别提供 `/api/updates/patches/{platform}` 与 `/api/updates/patches/files/{sha256}`。客户端只访问固定官方 HTTPS 地址，不接收服务器提供的任意下载 URL，不转发 Cookie、学习档案或认证令牌，不接受重定向。

6. 完整包先生成、校验、上传，再在对应 release 的 `installer` 记录固定版本文件名、字节数和 SHA-256。客户端重新读取官网清单，只从固定 `/downloads/ReadAge-版本-windows-x64-setup.exe` 或 Android APK 路径取包，不能接收任意地址。版本变化、大小不符或坏摘要均停止，已安装版本和个人数据保留。

生产信任公钥在 `config/update-trust.json`。本轮初始化的对应私钥位于忽略目录 `website/.data/update-signing-private.pem`；请妥善备份，不提交 Git、不放进安装包。也可用环境变量 `READAGE_UPDATE_SIGNING_KEY` 指定私钥文件。已有密钥绝不自动覆盖；更换公钥需要重新交付外壳，不能靠不可信的远端清单自行更换信任根。测试只用临时生成的另一套密钥。

外壳兼容指纹包含各端原生 / 服务源码、依赖锁、词典、模型清单及共用学习数据格式 / 数据库契约等；纯界面与版本号变化不改变指纹。数据格式变化不能作为普通网页小包直接套到旧外壳。发布器对未知资源格式直接报错，不静默省略；站点 manifest、扩展 ZIP、实验页、字体、许可证和静态媒体仍随文件清单完整交付。网页实验页的服务路径也跟随当前小更新。
