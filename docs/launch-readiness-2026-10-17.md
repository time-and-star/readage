## 最低要求与对应实现

1. 每次启动约 8 秒、运行中恢复联网重新检查；页面隐藏时保留意图，前台恢复后检查。原先失败也等待六小时的问题已修复，失败后一分钟可重试；成功后的普通后台检查仍间隔六小时。每分钟的定时器仅检测是否到期。更新检查不发送学习档案。
2. 我的学习 → 设置与工具 → 检查更新立即检查；即便用户此前暂不更新同一版本，主动检查仍显示卡片；无新版、失败分别反馈，不以失败冒充最新。
3. 检查并发合流，联网事件发生在旧失败请求内时保留一次后续重查；超时和取消可终止等待未响应的版本桥，不迟到弹窗。
4. 已安装或拒绝的小更新不再直接屏蔽更高完整安装版；若兼容的新 revision 可用仍优先提供小更新，否则按 Windows / web 数字外壳版本、Android versionCode 判断完整更新。卡片不会把拒绝的小更新误作为完整包动作。
5. 更新提示发生在应用运行 / 启动 / 恢复前台期间。没有加入应用关闭后的系统推送或后台常驻服务；手机被冻结时待恢复前台处理。此边界不能写成所有联网设备立即收到后台推送。

调度在 `src/lib/appUpdateSchedule.ts`、`appUpdateController.ts`、`useAppUpdates.ts`，三端共用；电脑调用受保护的 `server/appUpdateRoutes.ts` 固定官网地址，Android 调用 `NativeAppUpdateHttp` / `ReadageAppUpdatesPlugin`，没有把手机请求指向电脑 API。版本协议在 `website/update-protocol.mjs`，卡片在 `src/components/AppUpdateCard.tsx`。
